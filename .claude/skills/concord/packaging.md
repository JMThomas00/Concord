# Packaging, Releasing and Installing

## What a release is

One zip per server platform. Each holds an `<id>/` folder with
`plugin.toml` and the binary (Concord unwraps a single top-level folder):

```
dist/<id>_linux_amd64.zip     dist/<id>_linux_arm64.zip
dist/<id>_darwin_amd64.zip    dist/<id>_darwin_arm64.zip
dist/<id>_windows_amd64.zip
```

`go run release.go` (generated by the scaffolder, pure Go) builds them with
`CGO_ENABLED=0` and stamps the version from `VERSION` or the git tag into
`plugin.toml`. Extra files the plugin needs (a wrapped program, assets) go in
the zip too: add another `add(name, data, mode)` call in `release.go`
(mode 0o755 for executables).

Concord picks an asset by OS and CPU words in its file name (`linux`,
`darwin`, `windows`; `amd64`/`x86_64`, `arm64`/`aarch64`), so keep that
naming. A single platform-neutral zip is also accepted. Only `.zip` works
(no `.tar.gz`).

## Publishing on GitHub

The scaffolded `.github/workflows/release.yml` runs on a `v*` tag: it runs
the tests, builds the zips and attaches them to a GitHub release.

```bash
git tag v0.1.0 && git push origin v0.1.0
```

Creating a public repo and pushing a tag publish the code; confirm with the
user before doing either. Check the workflow run succeeded and the release
has five zips before telling anyone to install.

## Installing (admins, in the Concord client)

**Server Settings → Plugins → I**, then type one of:

- `owner/repo`: the latest release's zip for the server's platform
- a GitHub release asset link: that file
- any other https link to a zip

Verification is automatic: GitHub's published per-asset digest, else a
`<url>.sha256` file next to the zip, else https alone. The result says which
was used. The plugin ID comes from the zip's `plugin.toml`.

**Updating:** **U** then Enter uses `[plugin].source_url`. The update is
started and must connect within `startup_timeout_seconds`; otherwise the old
version is restored and restarted, and the failed one is kept for
inspection. **Uninstall** (X twice) removes only the plugin's folder; its data
folder, account and channels stay for a reinstall.

Needs **Manage Plugins** (or server owner). No restart, no files to edit.

## Versioning

- Bump the tag for every release; `U` compares nothing, it just installs the
  latest, so never re-point an existing tag.
- Keep `[plugin].id` stable forever: it names the data folder and service
  account. A new ID is a different plugin.
- Keep saved-data formats backward compatible, or migrate them on load.
